# CLAUDE.md — developing this repo

This repo is an **Obsidian theme + Claude-ready vault kit** (Demon Slayer / Tengen Uzui Entertainment District). It is *not* a user's vault. For the instructions that get installed into a vault, see `templates/vault-CLAUDE.md`.

## Layout
* `categories.json` — source of truth for categories/colours. Edit here, never hard-code category colours in CSS.
* `src/*.css` + `src/pixel-scene.js` — theme sources. `35-categories.css` and the `{{SCENE_RULE}}` token are filled by the build. The scene is generated pixel-art SVG (see dnd-game-brain/_builder/pixelart.ps1 for the original technique).
* `src/characters.json` — the nine character themes (palette, sky, fireworks, effect, blade). Drives `body.tg-char-<id>` CSS, per-character scenes and the Style Settings dropdown. The chibis are traced sprites: Tengen = `src/tengen-sprite.json` (user-approved, never change), the other eight = `src/hashira-sprites.json` (traced from the user's reference sheet); `tools/chibi.js` adds outlines and exports SVGs.
* `plugins/` — bundled Obsidian plugins: `dataview` and `obsidian-style-settings` (the theme switcher UI).
* `plugins/dataview/` — bundled Obsidian plugin (from dnd-game-brain), installed by `install`.
* `tools/vault.js` — the whole toolkit (Node, no dependencies). Mode is auto-detected: repo checkout vs. installed `.tengen/`.
* `theme.css`, `manifest.json` — GENERATED. Never hand-edit.
* `starter-vault/` — sample vault with the toolkit installed into `starter-vault/.tengen/`. Treat its `.obsidian/themes/…`, `.tengen/`, `CLAUDE.md` and `00 Hub/` auto-lists as generated.
* `snippets/` — CSS toggles copied into vaults on install. `live-fireworks.css` is GENERATED by `build` (it swaps the still scene for the animated one); the theme itself ships the still scene.

## After ANY change to `src/`, `categories.json`, `tools/` or `templates/`
```bash
node tools/vault.js build                 # regenerates theme.css + manifest.json (+ starter-vault theme, graph colours, link colours)
node tools/vault.js install starter-vault --structured # re-syncs the toolkit, CLAUDE.md, snippets into the sample vault (structured mode ONLY for starter-vault)
cd starter-vault && node .tengen/tools/vault.js hubs && node .tengen/tools/vault.js check   # must end RESULT: ok
```

## Rules
* **Friend installs must stay SAFE**: default `install` adopts the vault's own folders and must never create/move/edit notes or folders, never install plugins/hotkeys unless flagged, back up to `.tengen/backups/` (not beside notes). Only `autolink --write` may edit notes, and only by adding `[[ ]]`. Re-verify with a copy of `dnd-game-brain`: sha256 of all non-`.obsidian` files identical after install; stripped-of-brackets text identical after autolink.
* Look = PIXEL ART (user rejected the earlier neon/glow design). Hard borders, no rounding, block shadows, Pixelify Sans. Applies to both `.theme-dark` and `.theme-light`. Modals/menus stay opaque.
* Obsidian themes are CSS-only — no JavaScript in the theme.
* The scene lives in `body::before` (fixed, z-index -1, base64 SVG with SMIL animation). Keep `pointer-events: none` and the transparent-container rules in `20-chrome.css`.
* `vault.js` commands that edit existing notes must stay **dry-run by default** and back up once into `.tengen/backups/`; the installer must never move/delete user notes.
* Visual check: render `theme.css` in headless Chromium (Playwright is installed) against a mock DOM using Obsidian class names; there is no Obsidian binary in the cloud container.
